# Development

## Dependencies

* Python 3.12
* Jinja2
* Java 17
* Apptainer
* Nextflow

## Install the application

    cd edge-v3/workflows/Nextflow/metagenomics/nextflow/scripts/
    ./install_edgev3.sh
* All dependencies necessary to run the command line application are installed
* User is prompted to enter paths to the directories where you would like the projects and the nextflow intermediate files to be stored. It is recommended that at least 2 TB of disk space be available. You will also be prompted for where the reference data is stored. 
* Paths are exported as environment variables and saved to the .bash_profile file
* If you need to change these paths, you must update them in the .bash_profile file
* Logging information is saved in `edgev3_install.log`
   
## Run EDGEv3
```run_edge -h
usage: run_edge.py [-h] [--project-name PROJECT_NAME] [--status] [--project-code PROJECT_CODE] [--conf-json-file CONF_JSON_FILE] [--paired] [--fastq-files FASTQ_FILES] [--sra-accessions SRA_ACCESSIONS] [--platform PLATFORM] [--projects-dir PROJECTS_DIR] [--nextflow-out-dir NEXTFLOW_OUT_DIR] [--refdata-dir REFDATA_DIR]
                   [--opaver-web-dir OPAVER_WEB_DIR] [--template-file TEMPLATE_FILE]

run EDGE Nextflow pipeline

options:
  -h, --help            show this help message and exit
  --project-name PROJECT_NAME
                        Project name chosen by user
  --status              Query the status of an existing Nextflow job using the provided project code
  --project-code PROJECT_CODE
                        Project code for an existing Nextflow config file (if not provided, a new one will be rendered from the template and config JSON file)
  --conf-json-file CONF_JSON_FILE
                        Path to config JSON file used to define pipeline parameters and modules to run
  --paired              Indicates if the input files are paired-end
  --fastq-files FASTQ_FILES
                        Comma-separated list of paths to FASTQ files containing raw reads to be processed (if paired-end, provide pairs as R1_path,R2_path; separate multiple pairs with a comma)
  --sra-accessions SRA_ACCESSIONS
                        SRA Accession numbers
  --platform PLATFORM   Explicitly specify sequencing platform (e.g. illumina, nanopore, pacbio) instead of relying on detect_platform function to determine platform from input files
  --projects-dir PROJECTS_DIR
                        Path to directory for storing all project output directories
  --nextflow-out-dir NEXTFLOW_OUT_DIR
                        Path to output directory for Nextflow intermediate files
  --refdata-dir REFDATA_DIR
                        Path to reference data directory
  --opaver-web-dir OPAVER_WEB_DIR
                        Path to OPAVER web directory
  --template-file TEMPLATE_FILE
                        Path to template file used to render Nextflow config file
 ```   

EDGEv3 commands are launched using: `run_edge` and a correct combination of arguments:

To run a workflow:
* `run_edge --project-name PROJECT_NAME --conf-json-file CONF_JSON_FILE --fastq-files FASTQ_FILES`.
* This uses the default values (saved as environment variables in ~/.bash_profile) for `NEXTFLOW_OUT_DIR`, `REFDATA_DIR`, `OPAVER_WEB_DIR` and `TEMPLATE_FILE` and can be overriden by supplying the corresponding command-line argument
* `FASTQ_FILES` is a comma-separated list of fastq files if the files are interleaved. For paired files, enter them as R1_pair1,R2_pair2,R1_pair2,R2_pair2,... etc. and include the `--paired` argument.
* `PLATFORM` is inferred by the workflow code from the input files, but can be explicitly specified
* Optionally, `SRA_ACCESSIONS`, a commma separated list of SRA accession numbers can be used instead of local fastq files. 
* The workflow output files are stored in `PROJECTS_DIR/PROJECT_CODE`, `PROJECT_CODE` is generated by taking the first input file, removing the file extension and adding a random 8-character string. The output files from multiple runs using the same input files will be stored in different directories.
* workflow run logs are saved in `edge_run.log` 

To check the status of a run:
* `run_edge --status --project-code PROJECT_CODE`
